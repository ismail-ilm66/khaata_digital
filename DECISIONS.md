# Decisions log

Choices made where the spec (`specs/Master Build Specification …md`) was silent
or could not be followed literally. Newest milestone at the bottom.

| # | Topic | Decision | Why |
|---|-------|----------|-----|

| 33 | Udhaar segment | The Add sheet ships Expense / Income / Transfer in M2. The **Udhaar** segment arrives in M3 with People. | Udhaar entries need the People module (spec M3). `person_id` is already preserved on edit. |
| 34 | Cross-currency entry | The keypad types into whichever amount is focused (sent or received). The **rate is derived** (received ÷ sent) and shown, not typed. | One keypad, fewer fields; the stored `fx_rate_micros` stays consistent with the two amounts by construction. |
| 35 | Category on save | A category is optional; Save needs only an amount and an account, so the fastest path is + → digits → Save. Tapping a selected category clears it. | Matches Hysab Kytab's "No Category" usage (859 of 1,710 rows in the real export). |
| 36 | List grouping | The Transactions list is grouped by **budget cycle** (sticky glass header, e.g. "25 Sep – 24 Oct"), then by day with daily totals. | Spec 3.4: every date grouping respects the month-start setting. |
| 37 | Paging | Pages of 60 entries; a page never ends mid-day, so daily totals on screen are always complete. | Correct totals without a separate aggregate query. |
| 38 | Search | `LIKE` matching (wildcards escaped) over note, place, category, both account names and tag names, plus an exact amount match when the text parses as money. No FTS table. | Fast enough at personal scale (10k rows) with no schema change. |

## M3 — Budgets, people, recurring, reminders

| # | Topic | Decision | Why |
|---|-------|----------|-----|
| 46 | Udhaar is not income or spending | Person-linked entries move account balances but are **excluded** from cycle income/spent (Home), budget spending, daily totals and (M4) reports. They're shown neutrally, never income-green. | Lending a friend Rs 5,000 isn't spending it; counting it would wreck budgets. |
| 47 | Udhaar storage | "I gave" = expense with `person_id`, "I received" = income with `person_id`, no category. The balance is derived (+ = they owe me). Settle up opens the editor pre-filled with the outstanding amount and the right direction. | Spec 3.2 #7: every udhaar entry is a real transaction. No schema change. |
| 48 | Budget currency and ratio | Budgets are in the home currency; spending in other currencies isn't counted against them. Progress is an integer per-mille (spent × 1000 ÷ limit); green < 800, amber 800–1000, red > 1000. | No automatic FX in v1; no `double` in domain code (standing rule). |
| 49 | Budget cycle labels | A budget cycle is identified by its start month (#22), navigable with ‹ ›; "Copy last month" replaces same-category budgets. | Spec 3.2 #6. |
| 50 | Recurrence anchor | Rules store their first occurrence (`startAt`) and whether to remind in the `template` JSON. Every occurrence is computed from that anchor, so the 31st clamps to 28/29/30 and returns to the 31st. `day_rule` stays `clampToMonthEnd`. | Month-end safety without drift (spec 1.5 #7); no schema change. |
| 51 | Recurring materialisation | On app start, on resume, and by a 6-hourly WorkManager job (Android). Each rule's catch-up runs in one DB transaction that also advances `next_run_at`, so nothing is created twice. A rule whose template no longer validates is skipped without blocking others. iOS catches up on launch/resume only. | iOS background tasks need extra entitlement setup; launch/resume covers normal use. |
| 52 | Reminders | Local notifications at **9 am on the due day** (or within a minute if that morning has passed), in the app's chosen language, inexact scheduling (no exact-alarm permission). Permission is asked only when a reminder is first turned on. | Spec 3.1 #15; minimal permissions. |
| 53 | Repeat in the editor | Only new entries can start repeating. Managing rules (stop, reminder on/off) is under More → Recurring; full template editing comes with the M6 recurring manager. | Keeps the editor simple. |
| 54 | Month-start setting | Exposed now (More → General), not in M6, so budgets can be checked against a salary date on a device. | M3 acceptance needs it. |
| 55 | Calendar maths location | The standing rule widened from "only BudgetCycle" to "only `lib/core/dates/`", which now holds `BudgetCycle` and `RecurrenceSchedule`. | Recurrence needs month arithmetic too; it still lives in one tested place. |
| 56 | Database across isolates | `AppDatabase.open()` uses `shareAcrossIsolates: true`. | The background job and the app may both write. |

A category's colour comes from a stable hash of its id, so filtering never repaints the survivors. Badges keep their muted tints. | The badge tints failed colour-blind separation as chart fills. |

| 64 | Export delivery | Share (system share sheet via a temp file) or Save to device (system save dialog). "This view" exports the Reports period and filters; "Everything" exports all entries. No network. | Spec: no network outside backup. |

## M5 — Backup, restore, import

| # | Topic | Decision | Why |
|---|-------|----------|-----|
| 66 | Schema v2 | New table `import_hashes(hash PK, transaction_id → SET NULL, imported_at)`. Migration `from1To2` creates it; `drift_schemas/` snapshot v2; golden fixture `test/fixtures/golden/v2` (v1 rows + one hash). The golden generator now always writes the *current* version from shared rows (`golden_rows.dart`). | Standing rule: every schema change ships a migration and a golden fixture. |
| 67 | Import idempotency | Each record's fingerprint = SHA-256 of its source row cells (both rows for a paired transfer) **plus its occurrence number among identical records in the file**. Kharcha's own files also skip entries whose id already exists. | Two genuine Rs 100 chais on one day both import, once; re-importing a file adds 0. |
| 68 | `.xls` reader | Pure-Dart BIFF8 + Compound File reader (`xls_reader.dart`): SST with CONTINUE splitting, LABELSST, LABEL, NUMBER, RK, MULRK, FORMULA/STRING, BOOLERR. Verified cell-for-cell against xlrd on the real Hysab Kytab file. Numbers become their shortest exact decimal text; this file is the one reviewed exception to the "no `double`" rule test. | Hysab Kytab exports `.xls`; the `excel` package reads only `.xlsx`. No network, no native code. |
| 69 | Test fixtures | The personal Hysab Kytab file is never committed (`specs/*.xls` ignored). `tool/make_xls_fixtures.py` generates synthetic `hk_sample.xls` (same layout) and `biff8_cells.xls` (record-type and CONTINUE stress). A test imports the real file when present locally and checks **every account and person against the file's own ACCOUNT closing balance** (all 37 match). | Privacy, while still proving the real file imports correctly. |
| 70 | People in Hysab Kytab | Each "Account Name" gets a role in the preview. Suggested **person** when the name is used only in transfers and doesn't look like a money account (bank/wallet/card/savings words and PK bank names); otherwise account. Names with their own expenses/income can't become people. A transfer to/from a person becomes udhaar; transfers between two people and unpaired transfers on a person are skipped and listed in the report. | Sample: 33 of 37 HK accounts are people. The user confirms before anything is written. |
| 71 | Opening balances on import | From the ACCOUNT sheet. New accounts get theirs; an existing account with no entries and zero opening (e.g. the seeded Cash) adopts it. A new person's opening becomes an udhaar entry offset by an equal adjustment on the busiest account, so no account balance moves. | Imported balances equal Hysab Kytab's closing balances to the paisa. |
| 72 | Account types on import | wallet (Easypaisa, JazzCash, SadaPay, NayaPay, Payoneer…), bank ("bank", PK bank names, "Limited"), card, savings (savings, committee/BC, invest), else cash. | Spec 3.3 rule, slightly extended. |
| 73 | Generic CSV | Column mapper with a header-based first guess: date, amount required; type, account, category, note, tags optional; D/M/Y, M/D/Y or Y-M-D; a default account. Without a type column, negative = expense. CSV delimiter is auto-detected. | Spec 3.1 #10. |
| 74 | `.kharcha` format | ZIP: `manifest.json` (cleartext: schema/app version, created, row counts, accounts/entries/date range, SHA-256 per file), `data.db` (`VACUUM INTO` snapshot), `receipts/<file>` (stored, not recompressed). Encrypted: data.db + receipts sealed together as AES-256-GCM `payload.bin`, key = PBKDF2-HMAC-SHA256, 120,000 rounds, random 16-byte salt in the manifest. | Spec 3.4; preview works without the passphrase. |
| 75 | Restore safety | Verify hashes → write the DB to a temp file → open it on its own connection (migrates older schemas) → `integrity_check` + `foreign_key_check` → `ATTACH` and copy inside **one transaction** with deferred foreign keys → swap the receipts folder. Any failure rolls back; the live database is never closed or replaced, so no restart is needed. A safety copy of the current data is saved on the phone first. Backup history (`backup_meta`) stays the device's own. | Spec: "a failed restore can never destroy existing data". |
| 76 | Merge | Same-name accounts, categories (per kind), people, tags and events are matched by name and the backup's rows re-pointed; entries in both copies: newer `updated_at` wins; settings, budgets and import history keep this device's. Recurring templates' ids aren't re-pointed (rare; noted). | Spec "replaces or merges". |
| 77 | Destinations | File: system save/open dialogs (SAF / Files), owned by the user, survive uninstall. Google Drive: `drive.file` scope only, visible "Kharcha Backups" folder, keeps the newest 8. On-device copies (newest 8) are automatic: before imports/restores and weekly. | Spec 3.4; least-privilege Drive access. |
| 78 | Google sign-in configuration | OAuth client ids come from `--dart-define=GOOGLE_SERVER_CLIENT_ID=…` (Android, web client id) and `GOOGLE_IOS_CLIENT_ID=…` (iOS; also add its reversed id as a URL scheme). Without them the Drive rows are hidden and a note says file backups work everywhere. Needs a Google Cloud project with the Drive API and the app's package name + SHA-1 — owner action before release. | Can't be created from here; the app degrades cleanly. |
| 79 | Auto-backup | Weekly. Android: a daily WorkManager check (battery not low; Wi-Fi only by default) that backs up once 7 days have passed. All platforms: also checked on launch and resume. Always keeps a device copy; uploads to Drive when connected and retries next time if the upload fails. | Spec 3.4; iOS has no reliable periodic background task. |
| 80 | Home nudge | Shown when no backup has left the phone (file or Drive) for 14 days — device-only copies don't count — and only once there's data. A failed startup integrity check shows a red "restore from a backup" prompt instead. | Spec 3.2 #9. |
| 81 | Blocs | `BackupBloc` (status, back up now, auto/Wi-Fi toggles, Drive connect), `RestoreBloc` (wizard) and `ImportBloc` (pick → map → preview → report). Parsing, packing and unpacking run in isolates. | Spec 3.5 table, with restore split out of BackupBloc for a simpler wizard. |
| 82 | Internet permission | Android release manifest now declares `INTERNET`, used only by Drive backup. | Required for Drive; no other network code (standing-rule test). |

## Open items carried forward

- **Seed data on first run:** a Cash account (PKR) is created at database creation. Onboarding (M6) changes its currency if the user picks another default.
- **Reminder on-device test:** passed on the iOS 26 simulator (iPhone 17). Running it exposed two iOS bugs that are now fixed: the deployment target was raised to 14.0 (workmanager needs it), and the AppDelegate now sets itself as the notification delegate (without it, reminders that fire while the app is open are dropped). Android: `adb shell pm grant com.expensetracker.kharcha android.permission.POST_NOTIFICATIONS` then `flutter test integration_test/reminder_test.dart -d <device>`.
- **Google Drive client ids (owner):** create the Google Cloud OAuth clients (see #78) and build with the `--dart-define`s; until then Drive is hidden and file backups are the path.
- **Receipt backup on device:** `integration_test/backup_restore_test.dart` (attach → encrypted backup → restore on a fresh "phone" → view, byte-identical) passed on the iOS simulator.
